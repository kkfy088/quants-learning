## 一、产品概述

### 1.1 一句话定位

**面向供应链/业务分析师的"量化思维迁移学习平台"——用康奈尔笔记 + AI 助手 + 多场景对照的方式，帮学习者建立从"经验决策"到"可验证决策"的认知地图与实操能力。**

### 1.2 要解决的问题

| 痛点 | 现状 | 本产品的应对 |
|------|------|------------|
| 量化知识散落在金融领域，业务分析师难迁移 | 教程都讲股票，没人讲怎么用到销量预测 | **金融/电力/供应链三场景对照**——共同骨架 + 差异化决策 |
| 学了就忘，没有结构化思考框架 | 视频看完即忘，没有沉淀 | **康奈尔笔记布局**——线索/笔记/总结三层，强制主动思考 |
| 卡住没人答，AI 通用但不懂上下文 | 通用 ChatGPT 不知道你在学什么 | **场景感知 AI 助手**——带入当前课程/章节上下文 |
| 5 天速成只教敲代码不教判断 | "会跑模型"不等于"懂量化" | **认知优先**：方法论→理论→基础→实操 |
| API Key 明文存储有安全风险 | localStorage 直存 | **Web Crypto AES-GCM 加密**（PBKDF2 派生 + 5 次错误锁定） |

### 1.3 不做什么（边界）

- ❌ **不做实时行情/交易执行**——纯学习平台，不接券商 API
- ❌ **不做用户系统/付费**——单机静态站，无后端数据库
- ❌ **不做视频录制**——纯图文 + AI，视频作为外部资源链接
- ❌ **不做完整 RAG**——教材内容人工提炼为结构化数据，不做向量检索

## 二、目标用户

### 2.1 主要用户画像

**P1：供应链/业务分析师（Michelle 本人及同类）**
- 已有 pandas/Excel 基础，懂业务但不懂量化方法论
- 目标：把量化方法迁移到销量预测、库存优化
- 痛点：学了一堆工具，但不知道"什么时候用哪个"

**P2：量化入门学习者**
- 零基础或只会跑模型
- 目标：建立完整的认知地图
- 痛点：教程要么太深（数学推导）要么太浅（API 调用）

**P3：跨行业迁移者（如电力市场转供应链）**
- 已有某一领域的预测经验
- 目标：理解共同骨架，快速迁移
- 痛点：不知道哪些经验可迁移、哪些需要重新学

### 2.2 非目标用户

- 量化资深从业者（他们需要的是工程化部署，不是入门）
- 纯学术研究者（他们需要的是数学严谨性）
- 寻找"一键赚钱"的人（本平台明确拒绝"5天成为分析师"的承诺）

## 四、详细需求

### 4.1 康奈尔笔记布局（F2）

**用户故事：**
> 作为学习者，我希望页面分成三栏——左侧是关键问题/线索，中间是详细讲解，底部是我自己的总结——这样我能像康奈尔笔记法一样主动思考，而不是被动阅读。

**验收标准：**

| AC# | 条件 |
|-----|------|
| AC1 | 左侧栏显示当前课程的 3-5 个关键线索（cues），可点击直接发送给 AI |
| AC2 | 中间栏显示完整内容（HTML 富文本，含代码块、警示框、引用） |
| AC3 | 底部有 textarea，学习者可输入自己的总结，自动保存到 localStorage |
| AC4 | 切换课程时总结内容按 dayKey 隔离存储 |
| AC5 | 线索点击后自动填入 AI 输入框并触发发送 |

### 4.2 场景感知 AI 助手（F3）

**用户故事：**
> 作为学习者，当我学到"ARIMA 的 ADF 检验"卡住时，我希望 AI 已经知道我在学这一课，直接给我针对性的解释，而不是我从头解释上下文。

**验收标准：**

| AC# | 条件 |
|-----|------|
| AC1 | 模型使用 `deepseek-v4-pro`，thinking 模式开启，reasoning_effort=max |
| AC2 | 每次请求自动注入 system prompt，包含当前课程标题 + 前 3 个线索 |
| AC3 | 对话历史保留最近 10 轮，避免上下文爆炸 |
| AC4 | API Key 通过 Web Crypto AES-GCM 加密存储，密码错误 5 次锁定 15 分钟 |
| AC5 | 网络错误时显示友好提示，不白屏 |

### 4.3 进度追踪（F4）

**用户故事：**
> 作为学习者，我希望看到自己连续学了多少天、完成了哪些课程——这样我有成就感，也能判断自己有没有掉队。

**验收标准：**

| AC# | 条件 |
|-----|------|
| AC1 | 每节课底部有"✅ 完成今日"按钮，点击后标记完成并累加连续天数 |
| AC2 | 连续天数基于实际日期计算，跨天访问自动更新 |
| AC3 | Header 显示进度条（当前/总数） |
| AC4 | 完成状态按 `${track}:${dayId}` 隔离，不同 track 独立计算 |

### 4.4 四轨切换（F1）

**用户故事：**
> 作为学习者，我希望根据当前阶段自由切换学习轨——周末用 5 天速成建立认知，工作日用 100 天修炼深入，垂直落地时切到电力市场 90 天。

**验收标准：**

| AC# | 条件 |
|-----|------|
| AC1 | 顶部有 4 个 tab，点击切换，当前 tab 高亮 |
| AC2 | 切换时 dayIdx 重置为 0，从第一课开始 |
| AC3 | 每个 track 的 sidebar 独立显示对应内容列表 |
| AC4 | Book track 使用不同的内容组件（BookChapterView） |

### 4.5 API Key 加密存储（F8）

**用户故事：**
> 作为注重安全的用户，我不希望我的 DeepSeek API Key 明文存在浏览器里——任何人打开 DevTools 都能看到。

**验收标准：**

| AC# | 条件 |
|-----|------|
| AC1 | 首次使用输入 API Key + 设置密码（≥6 位） |
| AC2 | 使用 PBKDF2（200,000 次 SHA-256）从密码派生 AES 密钥 |
| AC3 | localStorage 仅存 `{salt, iv, ciphertext}`，全部 Base64 编码 |
| AC4 | 解密后 Key 仅存 JS 内存变量，关闭页面即清除 |
| AC5 | 密码错误 5 次锁定 15 分钟，防止暴力破解 |
| AC6 | 右侧面板显示状态：🟢 已解锁 / 🔒 已锁定 / ⚪ 未配置 |

## 五、非功能需求

### 5.1 性能

| 指标 | 目标 |
|------|------|
| 首屏加载（FCP） | < 2s（静态导出，CDN 加速） |
| AI 首字节响应 | < 3s（依赖 DeepSeek API） |
| 页面切换 | < 100ms（纯前端状态切换） |
| Bundle 大小 | < 100KB gzipped（当前 83KB） |

### 5.2 安全

| 要求 | 实现方式 |
|------|---------|
| API Key 不明文存储 | Web Crypto AES-GCM |
| 密码不存储 | PBKDF2 派生后即用即弃 |
| 无后端数据库 | 纯静态站，数据全在用户浏览器 |
| HTTPS | CloudStudio 自动提供 SSL 证书 |

### 5.3 可维护性

| 要求 | 实现 |
|------|------|
| 内容与代码分离 | `content/*.ts` 数据层，UI 零改动即可加内容 |
| 类型安全 | TypeScript strict 模式 |
| 单文件部署 | `next build` → 静态导出 → rsync 到 deploy/ |

### 5.4 可访问性（待完善）

| 要求 | 当前状态 |
|------|---------|

| 移动端适配 | ⚠️ 未优化（三栏布局在小屏会挤） |

## 六、技术架构

### 6.1 项目结构

```
quants-learning/
├── app/                    # Next.js App Router
│   ├── layout.tsx          # 根布局
│   ├── page.tsx            # 主页面（单页应用）
│   └── globals.css         # 全局样式
├── lib/                    # 核心逻辑层
│   ├── types.ts            # TypeScript 类型定义
│   ├── storage.ts          # localStorage 抽象
│   ├── deepseek.ts         # DeepSeek API + Web Crypto
│   └── utils.ts            # 工具函数
├── content/                # 内容数据层（独立维护）
│   ├── crash-course.ts     # 5天速成
│   ├── deep-track.ts       # 100天修炼
│   ├── track-power90.ts    # 电力市场90天
│   ├── book-measure.ts     # 《如何衡量万事万物》
│   ├── book-pyqt.ts        # 《Python量化交易实战》
│   ├── books.ts            # 教材聚合
│   └── static.ts           # 资源/速查/自测
└── scripts/                # 一次性脚本（PDF提取等）
```

### 6.2 部署流程

```
内容迭代 → next build → rsync out/ deploy/ → CloudStudio 部署 → git push
```

## 八、附录

### 8.1 术语表

| 术语 | 定义 |
|------|------|
| **Track** | 学习轨，如 5天速成 / 100天修炼 |
| **Day** | 一节课，对应某 track 的一天 |
| **Cue** | 康奈尔笔记的"线索"，左侧栏的关键问题 |
| **IC** | Information Coefficient，信息系数，衡量因子预测力 |
| **MAPE** | Mean Absolute Percentage Error，平均绝对百分比误差 |
| **WAPE** | Weighted Absolute Percentage Error，加权百分比误差 |
| **Web Crypto** | 浏览器原生加密 API，支持 AES-GCM/PBKDF2 等 |

### 8.2 关键设计决策记录

| 决策 | 选择 | 理由 | 替代方案 |
|------|------|------|---------|
| 框架 | Next.js | 文件路由 + 静态导出 + TypeScript 一站式 | Vue/Astro |
| 5天教学法 | 认知优先 | 成年人学复杂东西先建认知地图 | 实操优先（v1 已废弃） |
| Key 存储 | Web Crypto 客户端加密 | 纯前端场景的最佳折中 | 后端代理（需部署） |
| AI 模型 | DeepSeek V4-Pro Think Max | 中文场景强 + 成本低 | GPT-4/Claude |
| 内容管理 | TS 数据文件 | 类型安全 + 易迭代 | CMS/Markdown |
